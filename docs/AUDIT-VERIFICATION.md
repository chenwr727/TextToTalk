# 判据验证清单

为什么要这份清单：**单元测试通过 ≠ 判据在真实数据上能工作**。

`auditMp4` 就是反例：代码写了、调用点也在，但 Remotion 自带的 ffmpeg 没有 `rawvideo` muxer，
实际一次都没成功跑过——表面上却像是"已经核过了"。

下表记录每条判据：有没有真实运行入口、有没有在**真实数据**上跑过、
有没有做过**反向注入**（故意弄错一次，看它能不能报出来）。

## “没核”不能当成“通过”（已修的三处）

这类问题比漏写判据更危险：它让人以为已经核过了。已修：

| 场景                                               | 修前行为                                       | 修后                                                    |
| -------------------------------------------------- | ---------------------------------------------- | ------------------------------------------------------- |
| `assets/tts/<task>` 整个移走（16 句全缺音频）      | 打印「✓ 与真实音频一致」                       | `✗ 一句都没拿到真实音频，不是“一致”，是“没核”` + exit 1 |
| 模型漏生成 `narration`（有字幕、无口播稿）         | 静默跳过                                       | 「有 N 句字幕，但这一页没有口播稿」                     |
| 全部 34 个 `.browser.log` 缺失（元素级判据全没跑） | 只多一行“34 页没拿到 DOM 几何”，几乎和通过一样 | 额外打印「✗ 元素级审计整体没生效」+ exit 1              |

第三项顺带量出一个之前不知道的数字：缺几何时告警从 0 跳到 **15 页**——
说明有 15 页的判据依赖 DOM 几何，不只是“充实度”那一项。

## 一直核不出的（不是没写，是不存在可对照的参考）

- **语义错误**：同义词替换、因果写反。需要一份可信的参考语义；正文与字幕同源，一起错时互相印证不了。
- **语音快慢与断句是否合适**：量到真实语速 3.65–5.32 字/秒（正常范围），但没有"好听"的判定标准。
- **动画过程本身是否难看**：只能核结束态。入场期的越界与裁字告警实测全是假阳（已验证 5/34 页）。
- **长文案截断之后的整段**：观众看不到，无法核；能报的是截掉多少字。

## 为什么不把这些变成常驻负向样本

常驻负向样本只能表达"**数据自身就能表达的错**"。现有 34 个样本里只有
`points-icon-bogus` 属于这一类（不存在的图标 id 会被静默忽略）。

其余判据的错属于"**数据说 A、画面出 B**"：要么改数据、要么改渲染——
只改数据没用（渲染会跟着变，不会出现不一致）；改渲染又不能常驻（正常审计会一直报警）。
所以这些只能用**临时注入 + 重渲 + 看图 + 回退**的方式验证，上表已逐条记录。
